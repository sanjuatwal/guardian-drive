CURRENT FIRMWARE BEHAVIOR
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

On boot:
- Attempts MPU-6050 init over I2C (SDA GPIO8, SCL GPIO9).
- If init fails → activates simulation mode (no hardware needed).
- If init succeeds → uses real IMU data.

Runtime:
- Captures first 50 samples to set parked baseline (pitch/roll).
- On subsequent samples:
  - Computes delta vs baseline
  - If delta > 8.0 deg for 3 consecutive samples → fires tilt alert
  - Alert triggers state transition to SUSPICIOUS
  - Event logged via EventLogger: "EVENT|event_id=...|sensor_type=imu_tilt|severity=high|timestamp_ms=...|payload=..."
  
Serial commands:
- Press 'r' or 'R' to reset baseline and recalibrate (useful for testing after tilting).

Build status: ✓ PASSING (PlatformIO)
Code size: 5.9% RAM, 8.6% Flash (plenty of room for more modules)

Platform constraints / implementation notes:
   - Android: high-priority notifications, custom sounds, full-screen intents, and action buttons are supported more directly
   - iOS: critical alerts are possible only with Apple's Critical Alerts entitlement/approval; otherwise use high-priority push + custom in-app full-screen takeover after open
   - iOS action buttons on notifications are supported, but true alarm-style interruption is more restricted than Android
   - Custom Guardian Drive alert tone is feasible on both platforms, but iOS behavior depends on notification category + app permissions and may still be more constrained than Android
